## 2. Content Calendar Seed

Create workspace/marketing/calendar.json:
```json
{
  "items": [],
  "lastUpdated": null
}
```
Calendar items structure: { id, title, type (blog/social/email/case-study), product, status (planned/in-progress/draft/published), assignedAgent (strategist/writer/editor), dueDate, brief (string), draftFile (string or null) }

## 3. Backend (server.js)

New routes:

GET /api/marketing/team
- Read all .md files from workspace/marketing/agents/
- Parse frontmatter for each (name, role, description)
- Return: [{ id, name, role, description }]

GET /api/marketing/calendar
- Read workspace/marketing/calendar.json
- Return the calendar object

POST /api/marketing/calendar
- Body: { title, type, product, dueDate, brief }
- Validate with TypeBox
- Add new item to calendar.json with id, status='planned', assignedAgent=null
- Return the new item

PUT /api/marketing/calendar/:id
- Body: { status?, assignedAgent?, draftFile?, title? }
- Update the item in calendar.json
- Return updated item

DELETE /api/marketing/calendar/:id
- Remove item from calendar.json
- Return { ok: true }

POST /api/marketing/team/run
- Body: { agentRole: 'strategist'|'writer'|'editor'|'analyst', task: string, calendarItemId?: string }
- Read the agent persona file
- Query RAG for context (same pattern as /api/marketing/generate)
- Build a prompt combining: persona instructions + RAG context + task
- Save output to workspace/marketing/output/ as YYYY-MM-DD-{role}-{random}.md
- If calendarItemId provided, update that calendar item's status and draftFile
- Return: { id, filename, prompt, status: 'queued' }

TypeBox schemas for all the above.
